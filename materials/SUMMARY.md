# Урок 13 · Шпаргалка: ссылки и обновление данных

## 1. Значение и ссылка
- Примитивы (`number`, `string`, `boolean`, `null`, `undefined`) копируются **значением**.
- Объекты, массивы и функции — **ссылкой**: переменная хранит «адрес» объекта.
- `const b = a` для объекта — второй ярлык на **тот же** объект, не копия.

```js
const tea = { price: 180 };
const sameTea = tea;
sameTea.price = 200;
tea.price; // 200
```

## 2. Сравнение и const
- `===` у объектов сравнивает ссылки: `{} === {}` → `false`, `[] === []` → `false`.
- Сравниваем по полю: `item.id === id`.
- `const` запрещает переприсвоить переменную, но **не** запрещает менять содержимое.

## 3. Функции и мутация
- Объект-аргумент приходит ссылкой: `product.price = …` внутри функции меняет оригинал.
- **Мутация** — изменение существующего объекта или массива.
- Хорошая функция возвращает новые данные и не трогает входные.

## 4. Копия объекта — spread
```js
const copy = { ...tea };               // новый объект
const cheaper = { ...tea, price: 150 }; // копия + изменение
const wrong = { price: 150, ...tea };   // price снова 180!
```
Что правее — то и победит: изменения пишем **после** spread.

## 5. Массив без мутации
| Задача | Вместо | Пишем |
|---|---|---|
| Добавить в конец | `push` | `[...arr, x]` |
| Добавить в начало | `unshift` | `[x, ...arr]` |
| Удалить | `splice` | `arr.filter((i) => i.id !== id)` |
| Изменить один | `arr[i].qty = 2` | `arr.map((i) => i.id === id ? { ...i, qty: 2 } : i)` |
| Отсортировать | `arr.sort()` | `[...arr].sort()` |

### Шаблон обновления по id
```js
const next = list.map((item) =>
  item.id === id
    ? { ...item, field: newValue }
    : item
);
```

## 6. Вложенные данные
- Spread копирует только **первый уровень**.
- Меняете вложенное — копируйте каждый уровень пути:

```js
const moved = { ...user, address: { ...user.address, city: "Ош" } };
const tagged = { ...user, tags: [...user.tags, "react"] };
```
- `structuredClone(obj)` — полная глубокая копия.

## Методы массивов
| Меняют исходный ⚠ | Возвращают новое ✓ |
|---|---|
| `push`, `pop`, `shift`, `unshift` | `map`, `filter`, `slice`, `concat` |
| `splice`, `sort`, `reverse` | `[...arr]` |
| `arr[i] = x` | `find`, `some`, `every` — ничего не меняют |

## ⚠ Исключения и ловушки
1. `const arr = []` и `arr.push(1)` — работает: содержимое const-массива менять можно.
2. `sort` и `reverse` меняют исходный массив. Сначала копия: `[...arr].sort()`.
3. Стрелка возвращает объект только в скобках: `(i) => ({ ...i })`. Без скобок — `undefined`.
4. В `map` верните значение для **каждого** элемента, иначе получите `undefined`.
5. `find` возвращает ссылку из массива: изменили найденное — изменили массив.
6. `structuredClone` копирует всё целиком. Чтобы поменять одно поле, достаточно spread.
7. Переприсвоить параметр (`product = {…}`) — не меняет внешнюю переменную. Менять его свойства — меняет.
8. Строки неизменяемы: `toUpperCase`, `slice` и т.д. всегда возвращают новую строку.
9. `[...arr]` — новый массив, но объекты внутри те же: менять их через копию массива нельзя.
10. В `map` неизменённые элементы возвращаем как есть (`return item`) — копировать всё не нужно.

## Зачем
React сравнивает старое и новое состояние через `===`. Новый массив или объект — это сигнал «данные изменились, перерисуй». Сегодняшние приёмы — ежедневный код React.
